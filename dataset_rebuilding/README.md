# Dataset rebuilding

The IAB attribution task is too easy because the original captions (Qwen-VL-Chat,
~20-50 generic words) produce thin, poorly-made fakes that are trivially
separable from reals. We rebuild the synthetic side of the dataset in two steps:

1. **Re-caption the real images** with **dense, per-class captions** (40-80 words,
   diffusion-prompt style) generated by **Qwen3.5-9B** (vision, via Ollama).
2. **Regenerate the fakes** from those richer captions with the same diffusion
   generators IAB used (SD3, SD3.5, SDXL, FLUX), so the *only* variable vs the
   original IAB fakes is the richer prompt.

Everything runs on **CINECA Leonardo**, not locally.

## Where the data lives on CINECA

All project data lives under `$WORK/hyp_fine_tuning/` (a personal subdir of the
shared `$WORK` = `/leonardo_work/EUHPC_D26_009B`). Keep everything under this
subdir — bare `$WORK` is shared with other users. `$WORK` is set in your
environment on Leonardo.

| What | Path | Notes |
|------|------|-------|
| **Original real images** | `$WORK/hyp_fine_tuning/iab_dataset/` | `real/<Super>/<leaf>/*.{jpg,png,JPEG}` layout (20 000 imgs = 2 000 × 10 classes). This is the captioning input and the stem-mode generation input. |
| **Original IAB captions (thin) + fake-source CSVs** | `$WORK/hyp_fine_tuning/iab_captions/` | The original `*-new.csv` / `*.csv` files. Their **row order** defines the `_p{N}` index of every IAB fake — used by `--naming iab` to mirror the IAB fake set 1:1. |
| **New detailed captions (raw)** | `$WORK/hyp_fine_tuning/iab_captions_detailed/` | Output of Step 1; same filenames + schema as the original caption dir (drop-in). |
| **New detailed captions (cleaned)** | `$WORK/hyp_fine_tuning/iab_captions_detailed_clean/` | Deduped version (see `check_captions.py`). **This is the one generation reads.** |
| **New fakes (round 2)** | `$WORK/hyp_fine_tuning/iab_recap_dataset_v2/` | Output of Step 2, one subfolder per generator. Change with `--out_root` / `OUT`. |
| **HF weights cache** | `$WORK/hyp_fine_tuning/hf_cache/` | `HF_HOME`; populated by the setup scripts (compute nodes are offline). |

The 10 semantic classes and their on-disk layout (`SEMANTIC_DIR` in
`generate_fakes.py`):

## Step 1 — Re-caption the real images (Qwen3.5 via Ollama)

```bash
# ONE-TIME, on the LOGIN node (has internet): install Ollama + pull the model
bash dataset_rebuilding/setup_ollama_cineca.sh        # ~6.6 GB download

# Submit the captioning job (1× A100). Resubmit if it hits the wall-time —
# it skips images already captioned.
cd $WORK/hyp_fine_tuning/hyperbolic_CLIP
sbatch dataset_rebuilding/slurm_caption.sh
```

**Output**: CSVs in `$WORK/hyp_fine_tuning/iab_captions_detailed/`, same filenames + schema as the
original caption dir, keyed by image-filename **stem** (matching `IABCLIPDataset`):

```
COCO.csv                ImgPath,Caption
AnimalFace_cat.csv      ImgPath,Caption
...
imagenet-1k.csv         ImgPath,Label,Caption   (Label carried over by stem)
```

Then dedup → the clean dir that generation reads:

```bash
python dataset_rebuilding/check_captions.py \
    --captions_dir $WORK/hyp_fine_tuning/iab_captions_detailed \
    --write_clean  $WORK/hyp_fine_tuning/iab_captions_detailed_clean
```

### Changing the captioning style (e.g. "Van Gogh", "cartoon")

There are **two** places style can be injected — pick based on what you want:

1. **At generation time (recommended for a global restyle).** Keep the captions
   faithful to the reals and append a style suffix only when generating the
   fakes — see `--style` in Step 2. This restyles the *whole* fake set **without
   re-running the expensive captioning**, and keeps the caption files reusable.

2. **At caption time (changes what's described).** Edit the prompts in
   `caption_prompts.py`. `PROMPT_BY_SEMANTIC` maps each class to a prompt; the
   shared `_OUTPUT_RULES` string fixes the output format. To bias every class
   toward a style, add a line such as
   `"Describe the scene as if it were a Van Gogh oil painting: thick impasto
   brushstrokes, swirling skies, vivid complementary colors."` to the role intro
   (or to `_OUTPUT_RULES` so it applies to all classes). **Caveat**: this makes
   the model describe real photos in that style, which is less reliable than
   option 1, and you must **re-run the full Step-1 captioning** (~20k images).

   Always smoke-test before a full run:
   ```bash
   python dataset_rebuilding/caption_real_images.py \
       --dataset_path $WORK/hyp_fine_tuning/iab_dataset --output_dir /tmp/cap_smoke \
       --model qwen3.5:9b --smoke          # needs an Ollama server up
   ```

### Ollama version is pinned (do not bump blindly)

Leonardo's GPU driver is `535.274.02` (CUDA 12.2). **Ollama v0.30.x** ships CUDA
kernels this driver cannot load → every model crashes on load with
`CUDA error: device kernel image is invalid`. We pin **v0.24.0** (installed at
`$WORK/hyp_fine_tuning/ollama-0.24.0`), the last release that runs on this driver *and* supports
`qwen3.5`. `qwen3.5` is a reasoning model (~60 s of `Thinking…` per prompt); the
captioner sends `"think": false` (~0.4 s). Keep both.

## Step 2 — Regenerate the fakes (`generate_fakes.py`)

```bash
# ONE-TIME, on the LOGIN node: install diffusers + pre-download weights.
# SD3 / SD3.5 are GATED — accept their HF licenses and export HF_TOKEN first
# (see the header of setup_diffusion_cineca.sh).
bash dataset_rebuilding/setup_diffusion_cineca.sh     # SD3, SD3.5, SDXL
bash dataset_rebuilding/setup_flux_cineca.sh          # FLUX

# Generate. One job (= one GPU) per generator, in parallel:
cd $WORK/hyp_fine_tuning/hyperbolic_CLIP
sbatch dataset_rebuilding/slurm_gen.sh SD3
sbatch dataset_rebuilding/slurm_gen.sh SD3_5
sbatch dataset_rebuilding/slurm_gen.sh SDXL
sbatch dataset_rebuilding/slurm_gen.sh FLUX
```

Jobs are **resumable** — existing PNGs are skipped, so just `sbatch` again if a
job hits the 24 h wall-time. The 1024² models (~20k imgs each) often exceed 24 h;
shard by class to parallelise (second arg, one class per job):

```bash
sbatch dataset_rebuilding/slurm_gen.sh SD3_5 bedroom
sbatch dataset_rebuilding/slurm_gen.sh SD3_5 church
```

### Generator settings (match IAB — arXiv 2605.12967)

Defaults in `generate_fakes.py` `GENERATORS` reproduce the IAB settings exactly,
so the only variable vs the original fakes is the richer prompt. Override any of
them with the matching CLI flag if you need to.

| `--generator` | model | steps | guidance | dtype | resolution |
|---------------|-------|------:|---------:|-------|-----------|
| `SD3`   | `stable-diffusion-3-medium-diffusers`  | 28 | 7.0 | fp16 | 1024² |
| `SD3_5` | `stable-diffusion-3.5-medium` (not large) | 40 | 4.5 | bf16 | 1024² |
| `SDXL`  | `stable-diffusion-xl-base-1.0`         | 30 | 5.0 | fp16 | 1024² |
| `FLUX`  | `FLUX.1-schnell`                       |  4 | 0.0 | bf16 | 512²  |

### Key arguments to `generate_fakes.py`

| Flag | Default | Meaning |
|------|---------|---------|
| `--generator` | *(required)* | `SD3` \| `SD3_5` \| `SDXL` \| `FLUX`. |
| `--captions_dir` | *(required)* | Detailed caption CSVs keyed by stem — the `*_clean` dir. |
| `--out_root` | *(required)* | Where fakes go: `<out_root>/<GEN>/<semantic>/…`. **Change this to redirect output.** |
| `--naming` | `iab` | `iab` → `{prefix}_p{N}_i{K}.png` (mirror IAB 1:1); `stem` → `<stem>.png`. See below. |
| `--fake_src_captions_dir` | — | Original IAB CSVs (`COCO-new.csv`, …); **required for `--naming iab`** (maps row N → real stem). |
| `--dataset_path` | — | IAB root containing `real/…`; **required for `--naming stem`**. |
| `--variants` | `2` | Images per prompt in iab mode → `_i0`, `_i1` (IAB uses 2). |
| `--semantics` | all 10 | Subset of classes to generate. |
| `--style` | none | **Style suffix appended to every caption**, e.g. `"in the style of Van Gogh, oil painting"` or `"cartoon style, flat colors"`. Restyles the whole set without re-captioning. |
| `--max_per_class` | none | Cap prompts per class (quick pilots). |
| `--steps` / `--guidance` / `--dtype` / `--height` / `--width` / `--model` | per-generator | Override the IAB-matched defaults. |
| `--overwrite` | off | Regenerate even if the PNG already exists. |

### Generating a styled set (e.g. all Van Gogh)

`--style` is the clean way to make a fully restyled set. Via the SLURM launcher,
pass it as the `STYLE` env var (propagated to the job):

```bash
STYLE="in the style of Van Gogh, oil painting, thick impasto brushstrokes" \
    sbatch dataset_rebuilding/slurm_gen.sh SD3
# → every prompt becomes "<detailed caption>, in the style of Van Gogh, …"
```

Send a styled run to its own directory so it doesn't mix with the realistic set
(see "Changing where the output goes").

### Where the output goes (and how to change it)

Default destination is set by `OUT` in `slurm_gen.sh`:

```bash
OUT="$WORK/hyp_fine_tuning/iab_recap_dataset_v2"     # edit this, or pass --out_root directly
```

Layout (IAB structure, `--naming iab`):

```
$WORK/hyp_fine_tuning/iab_recap_dataset_v2/
  SD3/
    COCO/COCO-new_p0_i0.png
    AnimalFace/cat/AnimalFace_cat_p0_i0.png
    HumanFace/FFHQ/HumanFace_FFHQ_p0_i1.png
    Scene/bedroom/Scene_LSUN_bedroom_p3_i0.png
  SD3_5/  …
  SDXL/   …
  FLUX/   …
```

For a separate (e.g. styled) run, just point to a fresh root — non-destructive:

```bash
OUT="$WORK/hyp_fine_tuning/iab_recap_vangogh" STYLE="in the style of Van Gogh, oil painting" \
    sbatch dataset_rebuilding/slurm_gen.sh SD3
```

(`OUT` is read by `slurm_gen.sh`; for a direct `python` call use `--out_root`.)

### Naming convention of the new images

Two modes, chosen with `--naming` (`NAMING` env var in `slurm_gen.sh`):

- **`iab` (default) — mirror the IAB fake set 1:1.** Filename
  `{prefix}_p{N}_i{K}.png`:
  - `prefix` — per-class fake prefix (e.g. `COCO-new`, `AnimalFace_cat`,
    `HumanFace_FFHQ`, `Scene_LSUN_bedroom`, `imagenet-1k-new`).
  - `N` — the **row index into the original IAB fake-source CSV** for that class.
    Our detailed caption for the real image at row N supplies the prompt.
  - `K` — the variant index, `0..variants-1` (IAB uses 2 → `_i0`, `_i1`).

  So `HumanFace_FFHQ_p12_i1.png` = 2nd variant generated from the detailed
  caption of the real image at row 12 of `HumanFace_FFHQ.csv`. This requires the
  row N → real stem mapping, hence `--fake_src_captions_dir`.

- **`stem` — one fake per real image, named `<stem>.png`.** Used when the IAB
  fake-source stems don't match our captioned reals (e.g. **celebahq**: IAB uses
  CelebA-HQ 6-digit gender-split ids like `113099.jpg`, our reals are 5-digit
  `00003.png`, zero overlap → iab mode would skip the class). Stem mode iterates
  the real images directly (`--dataset_path`), so the caption always matches:

  ```bash
  NAMING=stem DATASET_PATH=$WORK/hyp_fine_tuning/iab_dataset \
      sbatch dataset_rebuilding/slurm_gen.sh SD3 celebahq
  ```

A prompt with no detailed caption is skipped (`nocap`). If a whole class is
missing from the output, the usual cause is a stem mismatch between the
fake-source CSV and the detailed CSV → use `stem` mode for that class.

```bash
python dataset_rebuilding/compare_fakes.py --new_naming iab    # pair new vs original IAB fakes
```

A quick PNG census per generator/class (run on the login node):

```bash
cd "$WORK/hyp_fine_tuning/iab_recap_dataset_v2" && for g in FLUX SD3 SD3_5 SDXL; do
  echo "== $g: $(find "$g" -name '*.png' | wc -l) =="
  find "$g" -name '*.png' | sed "s#^$g/##; s#/[^/]*\$##" | sort | uniq -c
done
```
